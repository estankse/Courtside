界面流程会创建一个独立的临时测试赛事，采用3分、1局获胜缩短验收时间，依次执行：裁判登录、找到指定赛程、接受任务、赛前准备、开赛、切换明暗模式、触控加分、中场间歇、确认本局、双方确认、提交成绩、切换赛事组登录、选择赛事、核验结果；最后从服务端读取比赛，断言状态为 FINISHED。正常赛事默认规则为21分、三局两胜。

同时检查了 Room 已持久化的逐分记录。共享业务规则和提交协议的检查由单元测试及服务端测试承担。现场断网与应用重启恢复可按下方操作继续人工验收，不把单次界面流程当作所有异常场景的保证。

## 推荐演示顺序

1. 启动服务，在两个应用登录页确认服务地址。模拟器通常使用 `http://10.0.2.2:8080/api`；真机填写电脑的局域网地址。已用 ADB reverse 的设备可以填写 `http://127.0.0.1:8080/api`。
2. 赛事组用 `organizer` 登录，裁判用 `referee` 登录，演示密码均为 `Courtside2026!`。
3. 在赛事组“管理资料”查看参赛者、场地和裁判；用“编排比赛”保存一场草稿，然后发布。
4. 裁判打开“我的赛程”，刷新、查看详情并接受任务；在赛前准备中设置初始发球方，再开始比赛。
5. 计分页点击蓝红双方区域，观察发球、奇偶发球区、撤销、交换显示和自动间歇。可切换浅色模式。
6. 比赛在线开始后，暂时停止服务，等待客户端同步失败，再继续计分；保存返回并关闭、重开应用，从原场次继续。再次启动服务，等待恢复同步。
7. 正常完赛后让双方现场确认并提交；断网提交时先显示保存在本机，收到回执后显示等待核验。
8. 赛事组从“成绩”核验，或填写原因退回；裁判刷新后在原设备更正局分、填写原因、重新让双方确认并提交。
9. 确认正式结果。全部比赛完成或取消后，在赛事设置中归档。

快速完整演示时，可以新建一项3分、1局获胜的赛事；这些规则属于该赛事配置，不会改变其他赛事。首版的后续轮次对阵由赛事组手工编排。

## 复现命令

```powershell
./scripts/build.ps1
./scripts/start-server.ps1 -Background
# 连接已启动的 Android 设备后
./scripts/test-ui.ps1 -Serial emulator-5556 -UseAdbReverse
```

构建与测试报告位于项目同级 `tmp/builds`，日志、截图及本次测试数据库备份也保留在 `tmp`。界面测试会向当前连接的服务创建测试赛事，应使用开发数据库运行。

## 验证边界

本次运行使用本机 Spring Boot 与 H2 文件库；已提供 MySQL 和 Docker Compose 部署配置，尚未在当前环境实际运行 MySQL 容器，也未部署到公网云主机。公网部署还需要服务器、域名或访问地址及 HTTPS 配置。

未进行多裁判大规模负载测试、真实手机机型矩阵测试或数据库灾备演练。首版同步采用前台轮询；应用关闭后不保证收到即时通知。离线计分要求该场比赛已在线开始且仍使用原设备，卸载或清除数据会丢失尚未上传的记录。

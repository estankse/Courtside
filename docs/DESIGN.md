# 界面与交互设计

应用名为羽序，英文标识 Courtside。视觉以深墨色、荧光浅绿、蓝红双方色和斜切细节构成。球场和羽毛球图案由 Compose Canvas 绘制，不依赖网络图片。比赛中选手姓名使用开源 Zhi Mang Xing 字体，许可证随应用保留。

## 裁判端

工作台强调下一场任务、待接受数量和未同步成绩；赛程按日期分组，可筛选状态。比赛详情先展示对阵、日期、场地、裁判和规则，再给出符合当前状态的主操作。

赛前随机结果只决定优先选择权，不直接把随机胜者写成先发球者；裁判根据现场选择设置首先发球方。计分后遵循赢者发球，以发球方当前分数奇偶提示左右发球区。

计分页按可用空间布局，两侧区域均可触控加分；数字变化使用短淡入和位移动画，点击有轻触感。发球提示与局点、赛点同时保留，避免动画替代重要信息。提供浅色模式以适应明亮场馆；系统返回或保存返回都保留本地记录。不会用退出计分等价于清空比分。

间歇倒计时、局结束确认和弃权操作分别采用明确的交互。局末撤销与确认并列；弃权必须选胜方并说明原因。赛后轨迹用蓝红小格表示每分得分方，并保留序号。双方分别确认后再进入正式提交。

## 赛事组端

总览展示当前赛事、比赛总数、进行中与待核验数量，并提供编排和管理资料入口。赛程卡片与裁判端采用同一结构，减少两端沟通成本。

编排表单从本赛事已有参赛者、场地和裁判中选择，时间使用日期与时间选择器。缺少基础资料时给出提示。冲突由云端拒绝并展示具体原因。成绩中心区分待核验和正式成绩，确认与退回均针对当前有效提交。

## 实现结构

Compose 页面由 UiState 驱动，CourtsideViewModel 处理用户操作，Repository 隔离 HTTP 与 Room。Room 记录以服务地址、用户和比赛分区；服务端与客户端共用计分规则，避免两份判定逻辑渐渐不同。

两个应用共用设计和数据模块，各自拥有独立应用标识、数据目录、登录状态与启动入口。后续可以按课程分工将 client 包中的赛事组页面、裁判页面和公共组件继续拆为 Gradle 子模块，而无需改变业务接口。
